# Региональные поддомены (город.example.ru) - что работает и где ломается

Опыт реального проекта: интернет-магазин инструмента на Битрикс + Аспро, 14 поддоменов городов-миллионников,
магазины только в одном городе, доставка ТК по России.

## Хронология типичного провала
1. Поддомены включены, но **301-редирект на основной домен** (или склейка старых зеркал) → Яндекс помечает их
   неглавными зеркалами. Регион назначить нельзя. Лечится только «Разгруппировкой адресов» (~2 недели).
2. Поддомен = **полная копия** сайта с другим городом в title. Google выбирает основной домен и убирает
   поддомены (трафик поддомена 17 → 0 визитов/нед за 5 недель); Яндекс начинает отдавать поддомену
   брендовые запросы основного сайта (каннибализация).
3. Заявка на регион без физического адреса **висит неделями** без ответа; `NOT_IN_SPRAV` остаётся.

## Технический чек-лист поддомена
- DNS-запись есть (wildcard не всегда).
- CMS не режет хост: Битрикс «Проактивная защита → Ограничение доменов» (`security/restriction_hosts_hosts`)
  даёт 302 на основной домен **из пролога** - в nginx/.htaccess его не найти.
- `canonical` ведёт на свой хост (абсолютные canonical, захардкоженные на основной домен, склеят всё).
- robots.txt поддомена: свой `Host`/`Sitemap`; отдаётся по `HTTP_HOST`.
- sitemap отдаёт **URL своего хоста** (статические карты генерятся с основным доменом - Вебмастер отклонит).
  Проверь и вложенные карты, особенно с точкой в имени (`sitemap-iblock-13.part1.xml`).
- Тексты/мета с городом: в Битрикс значения iProperty **развёрнуты** в `b_iblock_section_iprop` /
  `b_iblock_element_iprop` - правка шаблона не меняет существующие страницы.
- Склонения: в Аспро есть РП/ПП/ТП, **нет винительного** («доставка в Москву») - нужен свой словарь.

## Стратегия, которая имеет смысл
1. **Сузить индекс поддомена** до того, что отвечает на запрос «<товар> купить в <городе>»:
   разделы каталога, контакты/доставка, главная. Карточки товаров - `noindex, follow` (robots их от
   разделов по URL не отличит), бренды/блог/акции/компания - Disallow во **всех** группах robots.
   Sitemap поддомена - только эти страницы.
2. **Сделать оставшиеся страницы городскими по-настоящему**, из данных, а не шаблонной подстановки:
   службы доставки, реально используемые для города (по заказам), сколько заказов уже отправлено,
   что покупали из этого города, сроки/стоимость. Никаких выдуманных цифр и адресов.
3. **Страница-подтверждение региона**: город в теле страницы, честно «магазина в городе нет, отгрузка
   из <город>», условия доставки, телефоны. Без обещания «магазинов в Москве», если их нет.
4. Регион: заявка в Вебмастере + по возможности организация в Яндекс.Бизнесе (пункт выдачи/склад).
   Местный номер (виртуальный, с переадресацией) - дополнительный сигнал, не замена адреса.
   Номер-«заглушка» только для робота = клоакинг, риск санкций на весь домен.
5. Ускорить переобход: IndexNow + «Переобход» в Вебмастере для разделов поддоменов.

## Как мерить
- Вебмастер: `main_mirror` пуст, `searchable_pages` растёт, `NO_REGIONS` ушла.
- Метрика: `hosts` (поиск по поддоменам) и `landings --engine yandex` - входы на разделы с городом.
- Не путать: визиты на поддомен из других городов по брендовому запросу ≠ региональный трафик.
- Всплески «трафика» на поддомен с одной страницей за визит из облачных сетей - парсеры, не люди.
